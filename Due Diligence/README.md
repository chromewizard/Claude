## What this is

One canonical source for three audiences — investors, the Department of War, and technical reviewers — built so that each fact appears once, every file is hash-verified, and every release is reproducible.

The September data rooms diverged: same-named ZIPs with 22 vs 24 files; standalone decks differing from their data-room copies. That is the failure mode this structure removes. A package is *assembled* from canonical files, and the manifest proves which bytes went where.

## Rules

1. **One canonical file.** If two packages need it, they reference the same file; the build copies it and records the hash.
2. **Every release has a manifest.** `manifest.json` and `MANIFEST.md`, regenerated by `tools/build_manifest.py`. A file not in the manifest is not in the release.
3. **Claims discipline is the asset.** No document says a device exists, works, or will work. The two-question filter — *what is the net energy source, and where is the colder sink?* — applies to every sentence. Forward-looking statements carry the standard disclaimer.
4. **Forbidden label.** No file may contain the label defined in `tools/lint.sh` — in any form: name, handle, path, email, metadata, spreadsheet cell. The lint fails the build on a match. The founder is **Ian McLean**; the contact is `ian@energywave.ai`.
5. **Names.** Department of War → **DoW** in all new documents. "DoD" remains only in historical titles (the DoD white paper) and regulatory citations (DoDD 5200.47E, DoDI 5200.39).
6. **Dates and versions.** `EnergyWave_<Name>_YYYY-MM-DD.ext` for deliverables; `YYYY-MM-DD_<topic>_<author>_vN.md` for working notes (Council convention). Version history lives in `SOURCE_LEDGER.md`.
7. **Originals are never edited.** A correction produces a new dated file; the original stays, hash-recorded, in its source location.
